# Reusing diagramatic

[diagramatic](https://github.com/rororowyourboat/diagramatic) is the generic diagram toolkit. This repository supplies engineering notation, source references and explicit interchange contracts.

The optional bridge currently reuses the real `grid_layout` and `detect_overlaps` implementations from commit `baba9c95ea4b2783ae77d205bd958745d6eb9b83`. It imports an explicitly selected trusted source checkout and requires that revision with no tracked changes. It installs no dependencies and copies no upstream code or icon assets. The upstream project declares MIT in `pyproject.toml`; its checked revision has no standalone LICENSE file.

## Responsibilities

| diagramatic | mbse-diagrams |
| --- | --- |
| Generic layout and bounding-box overlap detection | SysML/UML profiles and SVG symbols |
| Existing Excalidraw/library tools, not yet bridged | Model references and semantic relationship types |
| Future optional Dagre backend | Source adapters, view schema, SVG/HTML/draw.io export |

The bridge changes only node positions and connector geometry. Engineering IDs, references, labels, relationship kinds and endpoints survive unchanged. Edge routing is generated by the MBSE adapter; diagramatic grid supplies node layout only. Node bounds are checked for overlap. Connector crossings and text overflow are not checked by this integration.

## Use

With a clean checkout of diagramatic at the tested revision:

```bash
python3 -m mbse_diagrams layout examples/communication/diagram.json \
  --diagramatic-path ../diagramatic \
  --layer Participant=types \
  --layer Sender=participants \
  --layer Receiver=participants \
  --layer Channel=transport \
  --layer Exchange=context \
  -o /tmp/layout.json --report /tmp/layout-report.json
python3 -m mbse_diagrams html /tmp/layout.json -o /tmp/layout.html
```

`--direction` supports TB, BT, LR and RL. Unassigned nodes enter a default layer. Layer order follows first occurrence in the input node list. The receipt identifies the engine commit, source hashes, preserved fields, geometry replaced and check limits.

The selected checkout executes Python code; select your trusted checkout explicitly. This is an optional source integration, not an installed production dependency.

## Evidence

The local integration suite exercised the actual checked-out engine: all three integration tests passed alongside fourteen core tests. Geometry and engineering-field preservation were checked independently. Run it with:

```bash
DIAGRAMATIC_PATH=/path/to/trusted/diagramatic python3 -m unittest discover -s tests -v
```

Without that environment variable, the integration tests skip explicitly. The ordinary CI does not download or execute another repository automatically.

The rendered HTML was browser-checked for five mapped nodes and text bounds, then visually inspected. See [integration evidence](../evidence/diagramatic-integration.json).

See the [generated layout](../examples/communication/diagramatic.html) and [conversion receipt](../examples/communication/diagramatic-report.json).

## Reuse candidates requiring more work

- Dagre: optional Node dependency, explicit dependency approval and routing tests needed.
- Excalidraw: existing exporter generates new random IDs and generic shape/arrow styles; add model-reference metadata and notation loss reporting before bridging it.
- Icon library registry: defaults to local Downloads paths. Require portable explicit paths and asset provenance before distribution.
- PNG rendering: existing pipeline loads Excalidraw from a CDN and notes external adaptation. Verify attribution and runtime behavior before reuse.

No changes were made or pushed to diagramatic.
